# KAAE-007 — Continuous Discovery Engine

**Document Type:** Operational Specification
**Parent Document:** KAAE-001 (Knowledge & Asset Acquisition Engine)
**Status:** Canonical Implementation Specification
**Applies To:** All Production Profiles

---

# 1. Purpose

This specification defines the **Continuous Discovery Engine** — the subsystem responsible for autonomously and continuously discovering new resources from all connected providers. Per KAAE-001 §14, the KAAE shall operate continuously, whether producers are online or offline.

---

# 2. Core Principle

**Discovery never stops.**

The KAAE does not wait for a producer to request a resource. It proactively discovers, evaluates, and indexes resources so they are available when needed.

---

# 3. Discovery Tasks

Per KAAE-001 §14, the Continuous Discovery Engine shall perform:

| Task | Frequency | Description |
|---|---|---|
| Monitor APIs | 15 min | Poll connected API providers for new resources |
| Monitor RSS feeds | 10 min | Check RSS feeds for new entries |
| Monitor provider updates | 30 min | Check for new resources from web-scraped providers |
| Refresh metadata | 24 hours | Update stale metadata for existing resources |
| Verify licensing | 7 days | Re-verify license status (per KAAE-004) |
| Repair broken links | 24 hours | Attempt to repair or flag broken resource links |
| Discover new assets | Continuous | Proactively search for resources matching collection goals |
| Import new resources | Continuous | Download and cache newly discovered approved resources |
| Update registry | Real-time | Create/update registry records for all discoveries |
| Generate previews | On discovery | Auto-generate previews and thumbnails |
| Run QA | On discovery | Auto-evaluate quality of newly discovered resources |

---

# 4. Discovery Layers

Per KAAE-001 §3, discovery operates in three layers:

### 4.1 Layer 1: Known & Trusted
- Providers with `relationship_status = verified` or `connected`
- High-trust providers (trust_score > 70)
- Discovery is aggressive and automatic
- Resources auto-enter the pipeline with minimal friction

### 4.2 Layer 2: Trusted Expansion
- Providers with `relationship_status = under_review`
- Medium-trust providers (trust_score 40-70)
- Discovery is cautious — resources require verification before entering pipeline
- QA threshold is higher

### 4.3 Layer 3: Intelligent Exploration
- New providers discovered through research
- Low-trust or unrated providers
- Discovery is experimental — resources require full verification + producer approval
- Used to expand the provider ecosystem

---

# 5. Discovery Strategies

### 5.1 Feed-Based Discovery
- Monitor RSS/Atom feeds from news providers
- Monitor API changelogs and "new resources" endpoints
- Automatically ingest new entries as they are published

### 5.2 Query-Based Discovery
- Run scheduled searches against provider APIs using:
  - Active collection goals (per KAAE Collection Goals)
  - Trending topics in the current production context
  - Producer-specified search queries
  - AI-suggested search terms based on production gaps

### 5.3 Gap-Based Discovery
- Analyze the existing Asset Library for gaps
- Identify resource types or categories that are underrepresented
- Proactively search for resources to fill those gaps
- Example: "We have no SVG icons for 'finance' — search for them"

### 5.4 Demand-Based Discovery
- When a producer searches for something and no results are found
- The query is logged as a "demand event"
- The Continuous Discovery Engine picks up demand events and searches for matching resources
- If found, they are indexed and the producer is notified

# 6. Collection Goals

The Continuous Discovery Engine is guided by **Collection Goals** — targeted acquisition objectives:

### 6.1 Goal Structure
```json
{
  "goal_name": "Finance Icons Collection",
  "description": "Acquire SVG icons for financial concepts",
  "target_resource_type": "svg",
  "target_category": "icon",
  "target_keywords": ["finance", "money", "banking", "investment"],
  "target_count": 50,
  "current_count": 12,
  "priority": "high",
  "status": "active",
  "deadline": "2026-08-01"
}
```

### 6.2 Goal Management
- Goals can be created by producers or auto-generated by the system
- Goals track progress toward target count
- Goals can have deadlines and priorities
- The discovery engine prioritizes searches aligned with active goals

# 7. Resource Processing Pipeline

```
Discovered
↓
Deduplication Check (per KAAE-003 §5)
↓
License Detection & Classification (per KAAE-004)
↓
QA Evaluation (quality scoring)
↓
Preview & Thumbnail Generation
↓
Indexing (keywords, categories, tags)
↓
Registry Record Creation (per KAAE-003)
↓
Asset Library Entry (per KAAE-005)
↓
Available for Production Use
```

# 8. Scheduling & Automation

### 8.1 Scheduled Tasks
The Continuous Discovery Engine runs on scheduled intervals:

| Schedule | Task |
|---|---|
| Every 10 minutes | RSS feed monitoring |
| Every 15 minutes | API polling |
| Every 30 minutes | Provider update checks |
| Hourly | Gap analysis |
| Every 6 hours | Demand event processing |
| Daily | Content availability checks |
| Daily | Broken link repair attempts |
| Weekly | License re-verification |
| Weekly | Metadata refresh |

### 8.2 Event-Driven Discovery
In addition to scheduled tasks, discovery is triggered by:
- New collection goal creation
- Producer search with no results (demand event)
- New provider connection
- Production profile activation (search for profile-relevant assets)

---

# 9. Resource Budgeting

The Continuous Discovery Engine respects budget constraints:

- Each discovery cycle has a maximum number of resources to process
- Premium/paid resources require budget approval (per CAE economic controls)
- Free resources are prioritized
- The engine tracks cost per discovery and adjusts strategy accordingly

---

# 10. Offline Operation

Per KAAE-001 §14, the engine operates whether producers are online or offline:

- Discovery runs as a background service (scheduled automations)
- Results are stored and indexed without producer interaction
- When a producer comes online, newly discovered assets are available immediately
- Producers are notified of significant new discoveries via AppNotification

---

# 12. Canonical Rules

1. Discovery shall operate continuously, regardless of producer online status.
2. Discovery shall run in three layers: known/trusted, trusted expansion, and intelligent exploration.
3. Collection goals shall guide proactive discovery priorities.
4. Demand events (producer searches with no results) shall trigger targeted discovery.
5. Every discovered resource shall pass through deduplication, licensing, QA, and indexing before entering the Asset Library.
6. Discovery shall respect budget constraints and prioritize free resources.
7. Discovery scheduling shall include both timed intervals and event-driven triggers.
8. Newly discovered resources shall be available to producers immediately upon indexing.
